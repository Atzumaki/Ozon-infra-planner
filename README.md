# Планировщик мощностей IT-инфраструктуры

Портфолио-проект по предиктивной аналитике IT-инфраструктуры: прогнозирует
потребление CPU и RAM, рассчитывает необходимый резерв и подбирает целочисленный
набор серверов с минимальной совокупной стоимостью владения (CAPEX + OPEX).

> Проект не связан с Ozon и использует только синтетические данные.

## Зачем нужен этот проект

Репозиторий воспроизводит полный путь аналитического решения, а не только
обучение модели:

- временной ряд с трендом, недельной сезонностью, ретроспективной проверкой и
  95-процентным прогнозным интервалом;
- математическая оптимизация серверного парка с помощью MILP;
- явный расчёт CAPEX, OPEX, резерва и уже имеющихся мощностей;
- мультиагентный конвейер: агент прогноза → агент бюджета → агент рисков;
- типизированный REST API, CLI, Docker, манифест Kubernetes и CI;
- модульные и интеграционные тесты.

## Архитектура

```text
наблюдения + каталог оборудования
                 │
          агент прогноза
        тренд + сезонность
                 │ спрос + неопределённость
          агент бюджета
        MILP / минимум TCO
                 │ план мощностей
           агент рисков
                 │
       типизированный ответ API
```

Агенты — независимые компоненты с узкой ответственностью и типизированными
объектами передачи результата. Поэтому оркестрацию легко тестировать, а
`RiskAgent` впоследствии можно заменить LLM-агентом с вызовом инструментов,
не поручая языковой модели сам расчёт бюджета.

## Быстрый старт

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -e ".[dev]"
```

Запустить готовый сценарий на воспроизводимых синтетических данных:

```bash
infra-planner
```

Запустить API:

```bash
uvicorn infra_planner.api:app --reload
```

Интерактивная документация Swagger будет доступна по адресу
`http://127.0.0.1:8000/docs`. Основная точка API:

```bash
curl -X POST http://127.0.0.1:8000/v1/plan \
  -H "Content-Type: application/json" \
  --data @request.json
```

Схему `request.json` можно посмотреть в Swagger. Без входного файла CLI запускает
демонстрационный сценарий, а собственный JSON принимает так:
`infra-planner --input request.json`.

## Математическая модель

Для каждого ресурса строится прозрачная базовая модель:

```text
y(t) = β₀ + β₁t + β₂t² + β₃sin(2πt/7) + β₄cos(2πt/7) + ε
```

Плановая нагрузка равна максимуму верхней границы прогноза с добавленным
операционным резервом. Оптимизатор выбирает целые количества серверов `xᵢ`:

```text
min Σ xᵢ · (CAPEXᵢ + месяцы · OPEXᵢ)
при условиях:
     Σ xᵢ · CPUᵢ ≥ требуемый CPU
     Σ xᵢ · RAMᵢ ≥ требуемая RAM
     0 ≤ xᵢ ≤ доступное количествоᵢ, xᵢ ∈ ℤ
```

## Проверка качества

```bash
ruff check .
pytest
docker build -t infra-capacity-planner .
```

Тесты проверяют временной порядок и интервалы прогноза, точность на отложенной
выборке, оптимальность простого серверного набора, сценарий без допустимого
решения и HTTP-контракт.

## Возможные улучшения

- кросс-валидация со скользящей точкой отсечения и сравнение с LightGBM/Prophet;
- несколько дата-центров, сроки поставки и поэтапные закупки;
- вероятностные ограничения вместо фиксированного резерва;
- мониторинг дрейфа и фактической экономии в Prometheus/Grafana;
- LLM-агент для объяснения отклонений с безопасными инструментами только для чтения.
